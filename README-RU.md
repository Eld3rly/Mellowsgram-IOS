> **Статус:** экспериментальная версия в разработке. Mellowsgram не связан с Telegram или AyuGram и не является их официальным клиентом.

> **⚠️ Предупреждение:** проект всё ещё находится в разработке. Функции могут отсутствовать, не работать или работать неправильно. Сборка и запуск проекта на текущем этапе не рекомендуются. Дождитесь релиза.

## Что такое Mellowsgram

Mellowsgram — форк Telegram iOS с нативным интерфейсом Telegram и набором функций, вдохновлённых AyuGram Desktop. Проект не пытается переносить desktop-интерфейс один в один: изменения встроены в стандартные экраны, рендерер сообщений и системные взаимодействия iOS.

Основные принципы:

- использовать стандартный Telegram-рендерер сообщений и медиа;
- хранить Mellowsgram-данные локально на устройстве и отдельно для каждого аккаунта;
- не создавать фейковые Telegram-сообщения, которые могли бы влиять на синхронизацию, unread-состояние или реакции;
- централизованно контролировать сетевые побочные действия Ghost Mode.

## Возможности

### Spy & Ghost

Ghost Mode состоит из общего переключателя и отдельных политик:

- **Don't Read Messages** — не отправлять read receipts;
- **Don't Read Stories** — не отправлять прочтения историй;
- **Don't Send Online** — не отправлять online-пакеты;
- **Don't Send Typing** — не отправлять статус набора текста;
- **Go Offline Automatically** — не удерживать online-состояние;
- не отправлять upload-progress при активном Ghost Mode.

При этом:

- локальное состояние прочтения сохраняется;
- после выключения режима старые подавленные receipts не отправляются задним числом;
- выключение влияет только на новые действия;
- отправка сообщений и загрузка файлов не блокируются;
- все проверки проходят через MellowsgramGhostModeCoordinator, а не размазаны по интерфейсу;
- поведение является best-effort: клиент не может отменить то, что уже успел получить Telegram.

### Удалённые сообщения

До удаления Mellowsgram сохраняет локальный снимок сообщения. После удаления строка остаётся на исходном месте, а не заменяется отдельным Telegram-сообщением:

- сохраняются исходные MessageId, MessageIndex, направление и дата;
- используется обычный Telegram bubble и стандартный media renderer;
- добавляется компактная пометка «Удалённое сообщение» с иконкой корзины;
- переключатель Translucent Deleted Messages меняет прозрачность всей строки;
- сохраняются текст, подпись и доступные media descriptors;
- поддерживаются фото, видео, кружки, голосовые, аудио, файлы, GIF и стикеры;
- локально доступные медиа можно открыть стандартным Telegram viewer/player;
- long-press использует обычное меню: ответ, копирование, пересылка, сохранение и другие доступные действия;
- удалённые строки не участвуют в синхронизации, unread-состояниях и реакциях;
- медиафайлы не копируются в архив: используются только уже доступные ресурсы MediaBox.

Архивирование не применяется к Secret Chats, эфемерным и другим сообщениям, для которых сохранение нарушило бы исходную приватностную семантику.

### История редактирований

Перед обновлением текстового сообщения Mellowsgram сохраняет предыдущую версию:

- текст;
- entities;
- время изменения;
- идентификатор сообщения и аккаунта.

История открывается из контекстного меню обычного или удалённого сообщения, если сохранённые версии существуют. Экран показывает текущую версию и предыдущие версии от новой к старой; текст можно скопировать. История изменения медиа пока не реализуется.

### Медиа с таймерами

Для обычных cloud-чатов включён account-scoped обход клиентских autoremove/autoclear-таймеров:

- подходящие фото и видео не превращаются в expired-content после истечения локального таймера;
- обычный viewer/player можно открыть повторно;
- исходный индикатор таймера или view-once остаётся видимым как признак исходного сообщения;
- удаляются только consumable-ограничения display-копии, а не само медиа;
- Secret Chats и эфемерные сообщения сохраняют исходную семантику Telegram.

Если ресурс уже отсутствует локально и MediaBox не может его получить, архив не восстанавливает байты, которых на устройстве никогда не было.

## Настройки

В системных настройках Telegram пункт **Mellowsgram** находится выше **My Profile**. На главном экране Mellowsgram расположены кнопки категорий и ссылки; каждая категория открывается отдельным нативным экраном:

- **Spy&Ghost** — Ghost Mode, архив удалённых сообщений и истории правок, а также поведение историй;
- **Background Notifications** — регистрация Telegram Web Push через relay в Bark;
- **Appearance** — прозрачность удалённых сообщений, насыщенность цветов аккаунтов, размер стикеров и отметки времени, оформление каналов, вкладок, папок и списка чатов;
- **Profiles & Calls** — сведения профиля и чатов, подтверждение звонков и видимость номера;
- **Media & Voice** — качество и HD-фото, камера и PiP, ускорение загрузки и скачивания, перевод и распознавание голосовых;
- **Messages & Context** — действия контекстного меню, поведение сообщений и параметры ввода.

Ссылки на канал и GitHub находятся на главном экране. У слайдеров Appearance видны текущее значение и смысл минимального и максимального значения. Качество отправляемых фото и переключатель **Send HD Photos** находятся в **Media & Voice**, поскольку управляют отправкой медиа, а не оформлением.

Ghost Mode, архив удалённых сообщений и история правок хранятся отдельно для каждого аккаунта. Настройки оформления клиента общие для приложения, а параметры, которые уже принадлежат Telegram, продолжают использовать его общее хранилище.

В клиент добавлены альтернативные иконки Mellowsgram, включая варианты, которые в Telegram обычно доступны только с Premium. Для уведомлений через Bark клиент регистрирует Telegram Web Push через relay и не удерживает сессии Telegram в фоне. Пока совместимый relay не развёрнут и не введён ключ устройства Bark, уведомления работать не будут. Relay расшифровывает payload Telegram перед отправкой в Bark, поэтому его оператор может видеть текст уведомлений.

Mellowsgram позволяет подключить до **32 аккаунтов** без зависимости от Telegram Premium. У каждого аккаунта остаётся отдельная Telegram-сессия и локальные данные.

## Приватность и ограничения

- архив удалённых сообщений и история правок не синхронизируются между устройствами;
- данные хранятся локально в Postbox текущего аккаунта;
- в архиве нет копий медиафайлов, только текст, entities, метаданные и descriptors;
- Secret Chats, ephemeral и privacy-sensitive сообщения исключены из архива и обхода таймеров;
- удалённые строки не становятся частью основной Telegram-истории и не создают fake-сообщений;
- Ghost Mode не гарантирует абсолютную невидимость и может нести риски для аккаунта и соответствия Terms of Service;
- проект экспериментальный — для проверки лучше использовать тестовый аккаунт.

## Сборка

Поддерживаемый способ сборки — **только GitHub Actions**. Локальные Xcode/Bazel/Make/IPA-сборки для рабочего процесса Mellowsgram не требуются.

Workflow:

1. получает исходники и submodules;
2. генерирует игнорируемый файл конфигурации;
3. восстанавливает Bazel disk cache;
4. собирает simulator IPA;
5. загружает IPA как Actions artifact.

В simulator workflow намеренно нет отдельного этапа unit-тестов. Конфигурации, API-ключи, сертификаты, provisioning profiles и IPA нельзя коммитить в репозиторий.

### Secrets GitHub Actions

Перед запуском workflow нужны Secrets:

| Secret | Назначение |
| --- | --- |
| TELEGRAM_API_ID | API ID приложения Telegram |
| TELEGRAM_API_HASH | API hash приложения Telegram |
| APPLE_TEAM_ID | Не нужен для обычного simulator-only артефакта; используется для заранее сформированных device-entitlements |

Основной bundle identifier проекта — com.mellowsgram.ios. Для расширений и App Groups генерируются согласованные идентификаторы.

### Генерация локальной конфигурации

Команда ниже только создаёт игнорируемый JSON и ничего не собирает:

    export TELEGRAM_API_ID="..."
    export TELEGRAM_API_HASH="..."
    export APPLE_TEAM_ID="XXXXXXXXXX"

    python3 ci/mellowsgram_configuration.py \
      --output build-input/mellowsgram-configuration.json \
      --api-id "$TELEGRAM_API_ID" \
      --api-hash "$TELEGRAM_API_HASH" \
      --team-id "$APPLE_TEAM_ID" \
      --bundle-id com.mellowsgram.ios \
      --url-scheme mellowsgram

Запуск workflow через GitHub CLI:

    gh workflow run build.yml --ref indev

После завершения нужно скачать IPA-artifact и установить его на совместимый iOS Simulator через simctl. Для simulator IPA подпись устройства не требуется.

## Установка на устройство

Для физического iPhone IPA необходимо переподписать собственным Apple-сертификатом и provisioning profile. Финальную переподпись могут выполнить AltStore или SideStore. Скрипт подготовки entitlements находится в ci/mellowsgram_sideload.py.

Не добавляйте в репозиторий сертификаты, provisioning profiles, API hash или сгенерированные конфигурационные файлы.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| submodules/Postbox | локальный архив сообщений и координация Ghost Mode |
| submodules/TelegramCore | настройки аккаунта, проекции архива, таймеры и сетевые ограничения |
| submodules/TelegramUI | рендеринг чатов, медиа, контекстные меню и пункт настроек |
| submodules/SettingsUI | корневой экран Mellowsgram и экраны категорий |
| ci/ | генерация конфигурации и подготовка sideload |
| .github/workflows/ | сборка simulator IPA через GitHub Actions |
